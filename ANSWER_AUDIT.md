## №2. Что требуется для использования CROSSTAB?

**Статус:** Уточнена формулировка

**Основной проверенный набор:**

- 1. Загрузка расширения tablefunc.
- 4. SQL-запрос (source_sql), возвращающий три колонки (идентификатор, категория, значение).

Для crosstab нужен модуль tablefunc и исходный SQL-запрос. Для простой формы запрос возвращает имя строки, категорию и значение.

**Оговорка:** Форма crosstab(source_sql, category_sql) допускает дополнительные исходные столбцы; три колонки обязательны для простой формы crosstab(text).

**Источники:** [PostgreSQL: tablefunc](https://www.postgresql.org/docs/current/tablefunc.html)

## №3. В каких частях SQL-запроса можно использовать VALUES?

**Статус:** Подтверждён

**Основной проверенный набор:**

- 1. В операторе INSERT для вставки нескольких строк.

**Обоснование повторной проверки:** VALUES синтаксически заменяет SELECT: подходит для INSERT, FROM, CTE и IN/сравнения в WHERE. Все варианты подтверждены.

**Оговорка:** Большинство не выбрало WHERE, однако в PostgreSQL допустимо, например, WHERE x IN (VALUES (1), (2)). При широкой трактовке верны все четыре варианта.

**Источники:** [PostgreSQL: queries-values](https://www.postgresql.org/docs/current/queries-values.html)

## №6. Какие элементы связаны с механизмом обновления материализованных представлений?

EXISTS проверяет наличие строк; NOT EXISTS — их отсутствие. Выходные столбцы обычно несущественны, поэтому часто пишут SELECT 1.

**Обоснование повторной проверки:** EXISTS проверяет наличие строк и допускает SELECT 1. NOT EXISTS истинен на пустом результате; содержимое результата само по себе не проверяется.

**Оговорка:** Содержимое строк не участвует в проверке EXISTS, но может влиять на наличие строк внутри самого подзапроса, например при INTERSECT.
